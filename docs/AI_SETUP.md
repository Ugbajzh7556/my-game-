# إعداد وكيل الذكاء الاصطناعي وREA

## دور كل مصدر

- **REA** أداة محلية للـCLI وMCP؛ الوكيل البرمجي يتصل بها ليحلل الأدلة والسلوك، ثم يستخدم النموذج الذي أعددته لديه للتفسير وكتابة الشيفرة.
- **awesome-free-llm-apis** قائمة وروابط لمزوّدين لديهم خطط مجانية أو حدود استخدام مجانية. ليست مكتبة تشغيل ولا تمنحك مفتاح API تلقائيًا.

## الإعداد على الكمبيوتر الذي يعمل عليه الوكيل

1. ثبّت إصدار Node.js الذي يتوافق مع REA: `22.19+` من سلسلة 22، أو `24.11+` من سلسلة 24، أو `26+`.
2. افتح الطرفية في حساب المستخدم نفسه الذي يشغّل أداة الذكاء الاصطناعي ونفّذ:

   ```bash
   npx rea-agents@latest setup
   ```

3. اختر عميل الذكاء الاصطناعي الذي تستخدمه، راجع التغييرات التي يعرضها REA ووافق عليها، ثم أعد تشغيل العميل. يدعم REA عدة عملاء مثل Claude Code وCodex وCursor وGemini CLI، وتعرض أداة الإعداد الخيارات المتاحة على جهازك.
4. اختر مزوّدًا من [قائمة الواجهات المجانية](https://github.com/mnfst/awesome-free-llm-apis) واضبط عنوان الخدمة والنموذج والمفتاح من إعدادات ذلك العميل/المزوّد. لا تضع المفتاح في هذا المستودع أو في محادثة عامة. الخطط المجانية قد تفرض حدودًا أو شروطًا أو تتغير.
5. افتح جذر المستودع `my-game-` داخل العميل حتى يقرأ [`AGENTS.md`](../AGENTS.md) ويعمل على الملفات الصحيحة.

لا يحتوي المستودع على `.mcp.json` بمسارات جهاز معيّن أو أسراره؛ سجّل REA في إعدادات المستخدم للعميل باستخدام أداة الإعداد الرسمية.

## مثال طلب للوكيل

> حلّل هذا التطبيق/الموقع الذي أملك إذنًا بفحصه باستخدام REA: `[ضع المسار المحلي أو الرابط]`. اعرض الأدلة والمراجع أولًا، وميّز الاستنتاجات والقيود. بعد ذلك أعد تنفيذ الوظائف/الصفحات التي أحددها داخل هذا المستودع، مع الحفاظ على ملفاته وبياناته الحالية، وشغّل الفحوصات المناسبة.

حدّد للوكيل بوضوح ما الذي تريد إعادة بنائه: صفحة أو تدفق استخدام أو ميزة بعينها. لا تفترض أن التحليل يستعيد الشيفرة الأصلية أو يطابق الهدف تمامًا.

## ملاحظات التوافق والخصوصية

- تعمل تحليلات REA محليًا على الكمبيوتر الذي يشغّل العامل/الوكيل. إذا رفعت ملفات فقط إلى مستودع GitHub، فهذا لا يجعل REA قادرًا على الوصول إلى ملفات جهازك تلقائيًا؛ أعطِ العميل مسارًا محليًا أو اتبع طريقة الاستيراد التي يدعمها.
- التحليل العميق لبعض الملفات الأصلية يعتمد على نوع الملف ونظام التشغيل وأدوات خارجية مثل Ghidra أو Hopper أو IDA أو JADX. افحص دليل REA المناسب قبل افتراض أن كل ملف مدعوم.
- قد يرسل وكيلك مقتطفات أو نتائج إلى مزوّد النموذج الذي اخترته. راجع سياسة الخصوصية وشروط الاستخدام لدى المزوّد، خصوصًا عند التعامل مع ملفات خاصة.
- استخدم REA فقط على تطبيقات ومواقع تملكها أو لديك إذن بتحليلها. أنشئ تنفيذًا جديدًا من الأدلة والوظائف المسموح بها، ولا تنسخ بيانات دخول أو شيفرة أو أصولًا محمية.
